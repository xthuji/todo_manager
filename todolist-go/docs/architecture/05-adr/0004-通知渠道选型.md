# ADR-0004：通知渠道选型（Messages.app + 微信客服消息）

- 状态：已接受
- 日期：2026-08-01
- 决策者：项目维护者

## 背景

天气通知需要触达用户本人。常见渠道有短信、邮件、推送、微信等。项目为个人单机应用，预算为零，需要免费可用的方案。

## 决策

采用**双渠道组合**：

1. **短信**：通过 macOS `osascript` 调用 Messages.app 发送 iMessage / SMS（[SendSMSMessage](file:///Users/huji/work/MyProject/code_mine/gitee/todo_manager/todolist-go/app/services/notify_service.go#L123)）
2. **微信客服消息**：通过微信公众平台客服消息 API 发送（[SendWechatMessage](file:///Users/huji/work/MyProject/code_mine/gitee/todo_manager/todolist-go/app/services/notify_service.go#L224)）

由 `notify_config.json` 的 `notifyTypes` 数组控制启用哪些渠道。

## 理由

1. **Messages.app 免费**：用户已有 macOS 设备与 iCloud 账号，iMessage 免费；即使对方非 iMessage 用户，也可通过 iPhone 中转发送 SMS（依赖 Continuity）。
2. **微信客服消息免费**：只需注册公众号（订阅号即可），无需付费 API；用户关注后即可接收消息。
3. **双渠道冗余**：iMessage 可能因网络问题延迟，微信作为备份；用户至少能在一个渠道收到通知。
4. **iMessage 接收方灵活**：`phoneNumber` 字段支持手机号与邮箱（iMessage 邮箱地址），便于在不同设备接收。

## 备选方案

| 方案 | 放弃原因 |
|---|---|
| 第三方短信服务（如阿里云） | 收费，且需注册实名 |
| 邮件（SMTP） | 延迟高，用户可能不及时查看 |
| Bark / PushDeer 等推送 | 需用户额外安装 App |
| Server酱（微信推送） | 免费版有次数限制，依赖第三方服务可用性 |
| Telegram Bot | 国内网络访问困难 |
| 桌面通知（osascript display notification） | 仅在 Mac 前才看到，不主动 |

## 后果

**正面**：

- 零成本实现双渠道通知
- iMessage 与微信都是用户日常高频查看的渠道
- 配置灵活（可单独启用某渠道）

**负面**：

- **短信仅 macOS 可用**：`osascript` 是 macOS 专属，Linux/Windows 桌面构建中 `SendSMSMessage` 会因 `osascript` 不存在而失败
- **微信客服消息限制**：用户需 48 小时内与公众号有交互才能收到，否则发送失败；且客服消息有 48 小时窗口限制
- **配置复杂**：需用户自行注册公众号、获取 AppID/Secret、关注并获取 OpenID
- **依赖外部 API**：微信 API 故障时通知失败
- **安全风险**：`wechatAppSecret` 明文存储在 `notify_config.json`，分发时需注意脱敏
