# ADR-0001：技术栈选型（Gin + webview_go）

- 状态：已接受
- 日期：2026-08-01
- 决策者：项目维护者

## 背景

Todolist-Go 由 Python + Webview 版本迁移而来，目标是在保留前端静态资源与 HTTP API 契约的前提下，用 Go 重写后端以获得：

- 单文件可执行部署（无需 Python 运行时）
- 更低的内存占用与更快的启动速度
- 跨平台一致的桌面体验

需要选择 Web 框架与桌面窗口方案。

## 决策

- **Web 框架**：`github.com/gin-gonic/gin` v1.9.1
- **桌面窗口**：`github.com/webview/webview_go`
- **HTML 解析**：`github.com/PuerkitoBio/goquery`（解析墨迹天气 HTML）
- **日志**：标准库 `log/slog`

## 理由

1. **Gin**：社区主流、文档丰富、性能足够；与 Python Flask 的路由组概念对齐，便于迁移。
2. **webview_go**：轻量（无 Electron 的 Chromium 包袱），用系统原生 WebView（macOS WKWebView / Linux WebKitGTK / Windows WebView2），体积小启动快；与 Python 版 webview 库 API 几乎一致，迁移成本低。
3. **goquery**：墨迹天气无公开 API，只能 HTML 解析；goquery 是 Go 生态中最成熟的 jQuery 风格解析库。
4. **slog**：Go 1.21+ 标准库，结构化日志，无需引入 zap/zerolog 等第三方依赖。

## 备选方案

| 方案 | 放弃原因 |
|---|---|
| net/http（无框架） | 路由分组、参数绑定、JSON 序列化需手写，工作量大于收益 |
| Echo / Fiber | 与 Gin 同质，无显著优势；Gin 社区资料更多 |
| Wails | 框架本身较重，需特定 build tags，与原 Python 版的 webview 模型差异大 |
| Electron | 体积过大（百 MB），与"轻量桌面应用"定位冲突 |
| zap / zerolog | 性能优势对单机桌面应用无意义；slog 已够用 |

## 后果

**正面**：

- 单可执行文件 + `static/` + `data/` 即可分发，无需运行时依赖
- 启动 < 1 秒，内存占用 < 100MB
- 与 Python 版的 API 路径与响应结构完全对齐，前端零改动

**负面**：

- webview_go 依赖各平台原生 WebView 系统库，构建时需安装 WebKitGTK（Linux）或 WebView2（Windows）
- Gin v1.9.1 较老，未来升级到 v1.10+ 需评估破坏性变更
- goquery 引入 cascadia 等 5 个间接依赖，增加 go.sum 体积
