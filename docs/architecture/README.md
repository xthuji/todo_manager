## 维护原则

1. 文档与代码同仓库，跟随提交演进；如代码变更影响架构，请同步更新对应章节。
2. 过期内容**标注而非删除**（在段落顶部加 `> ⚠️ 已过期（YYYY-MM-DD）：...`），保留历史决策痕迹。
3. 每次更新文档时，刷新顶部的"生成时间 / 代码版本"。
4. 所有架构图使用 Mermaid，不引入外部图片。
5. 代码引用使用 `file://` 绝对路径链接，便于 IDE 直接跳转。
